GeometricBase.State — Type

Holds the solution of a geometric equation at a single time step.

It stores all the information that is required to uniquely determine the state of a systen, in particular all state variables and their corresponding vector fields.

GeometricBase.StateVariable — Type

StateVariable{T,N,AT,RT,PT} is a wrapper around a AT <: AbstractArray{T,N} that holds one of the variables consituting the state of a dynamical system.

The value field holds the actual data, the range field holds the range of valid values, and the periodic field holds a bitmask indicating which dimensions are periodic.

GeometricBase.h5load — Function
h5load(T, h5, args...; path)
h5load(T, fpath::AbstractString, args...; kwargs...)

Read an object of type T from the group path of the HDF5 file or group h5, as written by h5save. The trailing arguments supply what the file cannot hold, for example the problem that a solution belongs to.

A method types h5 as HDF5.H5DataStore, and it chooses its own default for path. The second form opens the file fpath read-only, and calls the first form on it. See h5save.

GeometricBase.h5save — Function
h5save(h5, x; path)
h5save(fpath::AbstractString, x, args...; mode = "w", kwargs...)

Write x into the HDF5 file or group h5, under the group path.

A package that stores one of its types in HDF5 adds a method for that type, usually in a package extension on HDF5, so that one function serves every type. The method types h5 as HDF5.H5DataStore, and it chooses its own default for path.

The second form opens the file fpath with mode, and calls the first form on it with the other arguments. It is defined when HDF5 is loaded, and it works for every type with a method of the first form. An untyped h5 makes a method of the first form ambiguous with it.

GeometricBase.interface_violations — Function
interface_violations(x; include_missing = false)

The ways in which x breaks the contract of its abstract type, as a Vector of NamedTuples (; f::Symbol, kind::Symbol, detail::String): f names the function of the contract, kind the class of the violation, and detail what was found. An x that meets its contract gives an empty Vector, so an implementing package tests a value with @test isempty(GeometricBase.interface_violations(x)).

The method for AbstractMethod reports the kinds :throws, :type, :shadowed and :missing, the last only with include_missing = true. A method for a subtype may add kinds of its own, and names them in its docstring.

A method for a subtype calls the method of its supertype through invoke and appends its own entries. There is no method for Any, so a value without a contract raises a MethodError.

GeometricBase.interface_violations — Method
interface_violations(method::AbstractMethod; include_missing = false)

The violations of the contract of AbstractMethod by method, in the form of interface_violations, for its ten properties, in the order isexplicit, isimplicit, issymmetric, issymplectic, isenergypreserving, isstifflyaccurate, order, name, description and reference. Each property gives at most one :shadowed entry, and each call of a property at most one entry of the other kinds:

  • :shadowed: a module of the method binds the name of the property to a Function that is not GeometricBase's and has a method applicable to method or to its type, so a definition there does not reach GeometricBase's property. The binding is a definition in the module or an import; a binding that using brings in is not read, and a function with no such method is not a shadow. The modules of the method are the module of its type and each of its parents, up to the first module that is its own parent, such as the root module of a package, and never Main, Base or Core, unless the type is defined there. A module off this chain, such as a sibling submodule, is not read. detail names the module that owns the function, which can be a module off the chain. This entry comes before the entries of the calls.
  • :throws: the call of the property throws; detail names the exception's type. An InterruptException is thrown again.
  • :type: a property is… answers other than a Bool or missing, or order answers other than an Integer that is not a Bool, or missing; detail names the type of the answer. name, description and reference have no type rule.
  • :missing: the property answers missing on method; reported only with include_missing = true.

Each property is called on method. order, name, description and reference are also called on the type of method, and give the entries :throws and :type by the same rules; their detail ends in "on the type", and they come after the entries of the call on method. An answer missing on the type is no violation. Unlike for isAbstractMethod, an answer missing on method is no violation by default.

GeometricBase.isAbstractMethod — Method
isAbstractMethod(method)

true when method is an AbstractMethod whose ten properties isexplicit, isimplicit, issymmetric, issymplectic, isenergypreserving, isstifflyaccurate, order, name, description and reference all answer other than missing, and false otherwise. A property that throws makes isAbstractMethod throw. interface_violations lists the properties that throw, answer the wrong type, are defined again in a module of the method, or, on request, answer missing.

GeometricBase.noise — Function
noise(equation)
noise(problem)

The stochastic process driving a stochastic differential equation, an AbstractStochasticProcess.

The process says which noise drives the equation, not which realisation of it: drawing increments is the integrator's business, since only the integrator knows whether the scheme it implements needs increments that are accurate in the strong or the weak sense.

GeometricBase.noisedims — Function
noisedims(process)
noisedims(equation)
noisedims(problem)

The number of independent Wiener processes driving a stochastic differential equation.

This fixes the number of columns of the diffusion matrix, and it is what a stochastic integrator uses to size the increment vectors it draws each step — so it has to be answerable from the problem alone, before any integrator exists.

GeometricBase.vectorfield — Method

The vectorfield function returns a datastructure that stores the vectorfield for an AbstractStateVariable s that holds the state of a system. By default it returns a VectorfieldVariable that wraps zero(parent(s)), i.e., the same kind of array as the state variable, but custom methods can be implemented in order to account for more specific use cases, e.g., when s also contains constant fields that should not be present in the vector field.
